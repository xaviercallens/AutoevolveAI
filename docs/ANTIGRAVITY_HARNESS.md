## 1. Overview & Paradigm

The **Antigravity Harness** is a zero-trust, neuro-symbolic verification and execution framework designed for autonomous AI coding agents operating on the AutoevolveAI / ANSE platform. Under the **Physics of Computation** model, code generated by agents is never accepted based on natural language promises; instead, it is subjected to deterministic AST inspection, Lean 4 formal theorem verification, physical energy profiling ($E = w_t \cdot \text{Duration} + w_m \cdot \text{RAM}$), adversarial testing, and offline DPO trajectory alignment.

## 3. Detailed Component Specifications

### 3.1 Core Subsystem (`core/`)

#### A. `ContextOrchestrator` (`core/context_orchestrator.py`)
- **Purpose**: Manages large context windows (1M–2M tokens) for Gemini 1.5/2.0/3.x models without overflowing active memory budgets.
- **Key Methods**:
  - `estimate_tokens(text: str) -> int`: Fast token estimation from character count (ratio ~3.8).
  - `skeletonize_code(source_code: str, keep_docstrings: bool = True) -> str`: AST transformation (`CodeSkeletonVisitor`) replacing function bodies with `...` while preserving type signatures and docstrings.
  - `offload_large_output(identifier: str, output_text: str, max_inline_lines: int = 60) -> str`: Writes tool outputs >60 lines to `.scratchpad/<hash>.log` and returns an addressable head/tail pointer.
  - `pack_codebase(files: dict[str, str], priority_files: set[str]) -> dict[str, tuple[str, ContextTier]]`: Compresses codebase context, keeping priority files in full and skeletonizing non-priority files when budget is tight.
  - `slide_conversation_window(messages: list[dict], max_turn_tokens: int) -> list[dict]`: Preserves system/initial turn and recent turns under token limit.
  - `compact_unified_diff(diff_text: str, max_lines_per_hunk: int = 15) -> str`: Compacts long diffs while preserving diff and hunk headers.
  - `format_gemini_tool_declaration(...) -> dict`: Formats tools as Gemini FunctionDeclarations.

#### B. `AntiStubGuard` (`core/anti_stub_guard.py`)
- **Purpose**: Strict zero-trust AST auditor. Enforces physical penalty $E = 10^6$ (Maximum Pain) on code shortcuts.
- **Detected Violations**:
  - `EMPTY_BODY`: Functions containing only docstrings or empty bodies.
  - `PASS_STUB`: Single-statement `pass` in function body.
  - `ELLIPSIS_STUB`: Single-statement `...` in function body.
  - `NOT_IMPLEMENTED_STUB`: Raising `NotImplementedError` or `NotImplemented`.
  - `TRIVIAL_CONSTANT_RETURN`: Functions taking arguments but returning static constants (`return True`, `return 0`, `return []`) without computation.
  - `SILENT_EXCEPTION_SWALLOW`: `try ... except ... pass` blocks swallowing errors in production code.
  - `SYNTHETIC_MOCK_DATA`: Variables prefixed with `mock_`, `dummy_`, `fake_`, `sample_`, `test_data_` in non-test files.
  - `TIME_SLEEP_SIMULATION`: Calling `time.sleep` to simulate work in non-test logic.
  - `MOCK_INSTANTIATION`: Instantiating `Mock()`, `MagicMock()`, `PropertyMock()` in production files.

#### C. `Lean4Verifier` (`core/lean4_verifier.py`)
- **Purpose**: Interfaces with `lake` to verify mathematical soundness of formal proofs in `formal/`.
- **Key Methods**:
  - `extract_proof_inventory(dir) -> dict[str, list[str]]`: Categorizes `theorems`, `lemmas`, `axioms`, and `definitions`.
  - `scan_for_sorry(dir) -> tuple[int, list[str]]`: Scans Lean files for unproven `sorry` tokens.
  - `check_soundness(dir) -> tuple[bool, str]`: Asserts 0 `sorry` tokens and 0 unverified axioms.
  - `verify(extra_args) -> LeanVerificationResult`: Executes `lake build` and extracts compilation diagnostics.

### 3.2 Storage Subsystem (`storage/`)

#### `RedisBus` (`storage/redis_bus.py`)
- **Purpose**: High-throughput message streaming, JSON document persistence, and vector embeddings.
- **Resilience**: Automatically falls back to `InMemoryBusBackend` when local Redis server is not running, ensuring all tests and local operations run seamlessly without external infrastructure.
- **Key Methods**:
  - `publish_event(stream: str, payload: dict) -> str`: Appends event to Redis Stream.
  - `consume_events(stream: str, last_id: str, count: int) -> list`: Reads pending stream events.
  - `trim_stream(stream: str, max_len: int) -> int`: Enforces memory ceiling via `xtrim`.
  - `record_trace(trace: TraceRecord) -> str`: Persists execution traces and indexes by subtask.
  - `get_trace(trace_id: str) -> TraceRecord | None`: Retrieves trace by ID.
  - `store_vector(key: str, vector: list[float], metadata: dict)`: Stores embedding vector.
  - `search_vectors(query_vector: list[float], top_k: int) -> list`: Cosine similarity search.
  - `batch_search_vectors(queries, top_k) -> list[list]`: Batch similarity queries.
  - `set_with_ttl(key: str, value: str, ttl_seconds: int) -> bool`: Key storage with expiration.

### 3.3 Agents Subsystem (`agents/`)

#### A. `QAAgent` (`agents/qa_agent.py`)
- **Purpose**: Adversarial test generator exposing edge cases, recursion limits, and complexity traps.
- **Key Methods**:
  - `inspect_function_signature(func_code: str) -> list[tuple[str, list[str]]]`: Extracts function AST.
  - `generate_adversarial_suite(module_import: str, function_code: str) -> AdversarialTestReport`: Generates targeted Pytest test suite covering `None`, empty collections, numeric overflows (`sys.maxsize`, `float('nan')`, `float('inf')`), and stress strings (`'a' * 5000`).
  - `generate_property_tests(module_import: str, function_code: str) -> str`: Generates Hypothesis property tests (`@given(st.integers() | st.text())`).

#### B. `OptimizerAgent` (`agents/optimizer_agent.py`)
- **Purpose**: Profiles computational physics under the ANSE thermodynamic contract:
  $$E = w_t \cdot \text{Duration (ms)} + w_m \cdot \text{Peak RAM (MB)}$$
- **Thermodynamic Rule**: Hot-swap or algorithm promotion is valid iff $\Delta E = E_{\text{candidate}} - E_{\text{baseline}} < 0$.
- **Key Methods**:
  - `profile_callable(fn, *args, **kwargs) -> PhysicalEnergy`: Profiles duration and peak memory via `tracemalloc`.
  - `detect_algorithmic_bottlenecks(source: str) -> list[str]`: Identifies nested loops ($O(N^2)$) and linear `in` membership scans.
  - `detect_vectorization_opportunities(source: str) -> list[str]`: Identifies scalar loops replaceable by NumPy / PyTorch SIMD.
  - `estimate_theoretical_speedup(bottlenecks: list[str]) -> float`: Estimates speedup multiplier.
  - `compare_and_evaluate(base_fn, cand_fn, cand_source, *args) -> OptimizationProposal`: Full differential comparison.

### 3.4 Tests Runner Subsystem (`tests_runner/`)

#### A. `UnitIntegrationRunner` (`tests_runner/unit_integration.py`)
- **Purpose**: Runs Pytest suites with timeout protection, error classification, and JUnit XML output.
- **Key Methods**:
  - `run_pytest(test_path, extra_args, timeout) -> TestRunSummary`: Executes tests and extracts counts.
  - `run_with_junit_xml(test_path, xml_output_path) -> TestRunSummary`: Emits standardized CI JUnit XML.
  - `group_failures_by_exception(failures: list[str]) -> dict`: Groups failures by exception class.

#### B. `VisualRegressionRunner` (`tests_runner/visual_regression.py`)
- **Purpose**: Headless browser snapshot comparison for the Evolution Lab web dashboard (`web/server.py`).
- **Key Methods**:
  - `compare_images(baseline, candidate, diff_output_path) -> VisualRegressionResult`: Pure-Python pixelmatch algorithm computing mismatched pixels, difference percentage, and visual diff mask (changed pixels in red).
  - `generate_html_report(result, baseline, candidate, output_html) -> Path`: Standalone HTML side-by-side diff viewer.
  - `capture_screenshot_sync(url, output_path)`: Playwright screenshot capture.

---

### 3.5 RL Pipeline Subsystem (`rl_pipeline/`)

#### A. `TraceExtractor` (`rl_pipeline/trace_extractor.py`)
- **Purpose**: Aggregates recorded traces from `RedisBus` or offline JSONL into coherent development sessions.
- **Key Methods**:
  - `extract_from_bus() -> list[ExtractedSession]`: Aggregates live traces by `subtask_id`.
  - `extract_from_jsonl(path) -> list[ExtractedSession]`: Loads offline traces from disk.
  - `filter_by_time_window(sessions, start_ts, end_ts) -> list[ExtractedSession]`: Epoch filter.
  - `filter_by_energy_threshold(sessions, max_energy) -> list[ExtractedSession]`: Performance filter.
  - `compute_dataset_metrics(sessions) -> dict`: Pass rates, DPO-ready session counts, and mean energy.

#### B. `DPODatasetBuilder` (`rl_pipeline/dpo_dataset_builder.py`)
- **Purpose**: Constructs Direct Preference Optimization (DPO) training datasets.
  - **Chosen**: Passed verification, zero AST stubs, minimal physical energy.
  - **Rejected**: Failed verification, contains stubs/mock data, or higher physical energy.
- **Key Methods**:
  - `build_pairs_from_sessions(sessions) -> list[DPOPreferencePair]`: Extracts preference pairs.
  - `split_train_val(pairs, val_ratio, seed) -> tuple[list, list]`: Deterministic train/validation split.
  - `format_for_chat_dpo(pairs, system_prompt) -> list[dict]`: Formats samples for TRL Chat DPO (`prompt`, `chosen`, `rejected`).
  - `export_to_jsonl(pairs, output_path) -> Path`: Exports dataset to JSONL file.

## 4. CLI Command Reference

Execute via `uv run python -m antigravity_harness <subcommand>`:

```bash
# Audit Python source against stubs, mocks, and simulation shortcuts
uv run python -m antigravity_harness audit <file_or_dir> [--include-tests]

# Verify Lean 4 proof soundness (theorems, axioms, sorry tokens)
uv run python -m antigravity_harness verify [--formal-dir formal] [--build]

# Run unit and integration tests with structured telemetry
uv run python -m antigravity_harness test [tests/]

# Generate adversarial and property-based test suites for a function
uv run python -m antigravity_harness qa <file.py> [--module <module_path>]

# Build and export DPO preference dataset from execution traces
uv run python -m antigravity_harness dpo [--output results/dpo_dataset.jsonl]
```

## 5. MCP Tools (`mcp_guard_server.py`)

Registered with FastMCP under server name `agent-hardening-engine` (mounted in `.antigravity/mcp_config.json`):

| Tool Name | Parameters | Returns | Description |
|---|---|---|---|

| `verify_lean4_soundness` | `formal_dir: str` | `sound`, `inventory`, `message` | Scans Lean 4 proofs for sorry and ungrounded axioms |
| `generate_adversarial_qa_suite` | `module_import: str`, `function_code: str` | `pytest_code`, `property_test_code` | Synthesizes Pytest and Hypothesis test suites |
| `build_dpo_preference_dataset` | `output_path: str` | `pairs_generated`, `metrics` | Exports DPO preference pairs to disk |
