## 5. Issues

### M1 (major, not blocking) — the primary T2 verdict is PASS, not PARTIAL, when the frozen script is re-run in the environment the paper names
Locations: abstract "(verdict PARTIAL)"; Sec. 3.2 "The verdicts stay as preregistered"; Sec. 4.3 "PARTIAL is reported and stays"; Table 4 row "primary T2_H0 … no (soft: yes)"; Fig. 2; Limitations "Partial result"; Reproducibility (environment statement); Sec. 3.2 "That identity is expected from fixed seeds and the same code path".

Facts (Sec. 1 table): with `fit_real.py` unchanged except for the chain directory, `venv-cosmo` gives

|---|---|---|---|---|---|
| primary T1 H₀ | 68.5451 | 68.5490 | +0.0040 | 0.0107 | PASS → PASS |
| **primary T2 H₀** | **68.6970** | **68.6755** | **−0.0215** | 0.0140 | **PARTIAL → PASS** (|ΔH₀| 0.1670 → 0.1455) |
| secondary T1 H₀ | 68.5791 | 68.5776 | −0.0015 | 0.0107 | PASS → PASS |

The MAPs move by ≤ 10⁻⁷ (deterministic optimiser); only the chains move, by up to 1.5 committed MC errors. The `venv-pta` interpreter reproduces the committed G1 chain bit-for-bit and `venv-cosmo` does not, so the committed run came from `venv-pta` (Py 3.10, numpy 1.26.4, scipy 1.15.3), not from the `venv-cosmo` (Py 3.11, numpy 2.4.6, scipy 1.17.1) that the Reproducibility section names for the DESI runs. Neither `fit.json` nor `fit_real_stdout.txt` records the interpreter. Round 1's referee reproduced `fit.json` with 0 differing leaves, so that referee happened to use the same interpreter; the paper's two statements that fixed seeds make identity "expected" (Sec. 3.2, and the `secondary_vs_locked_preamendment` argument, `\hzLockDiff` = 0.0) hold only within one numerical environment: in `venv-cosmo` the re-run secondary differs from the hash-locked file by 0.0011 in T2 H₀.

Why this matters: the preregistered rule is applied to a posterior mean whose Monte Carlo error (0.014) is comparable to the margin over the strict window (0.017), and the paper already says so; but it then reports PARTIAL as *the* verdict ("stays"). The verdict is in fact not a property of the analysis but of the floating-point environment the chain happened to run in. The primary, headline-relevant DR1 check is PASS in one of the two environments on the authors' own machine. The same environment sensitivity also moves the G2 "post-hoc" numbers: the G2 offset becomes 0.102 Mpc and the implied shift 0.140 km s⁻¹ Mpc⁻¹ under `venv-cosmo` (inside the range the paper now quotes, so the Sec. 3.2 wording survives), and the "measured formula systematic" becomes −0.029 / −0.027 instead of −0.034 / −0.0044 (see m1).

What I ask for (no new analysis, no verdict re-tuning):
1. Record the interpreter, Python, numpy, scipy and emcee versions of every recorded run in the paper (Reproducibility) and, if the run JSONs cannot be edited, in `results/cosmo_synthesis/` from the evidence above; correct the sentence that names `venv-cosmo` for the H0 (and, per the DR2 preregistration's own `parent_import` note, the DR2) sampling runs.
2. State in the abstract, Sec. 4.3 and Limitations that the primary T2 label is environment-dependent: PARTIAL in the recorded `venv-pta` run (|ΔH₀| = 0.167), PASS on re-execution under `venv-cosmo`/numpy 2.4 (|ΔH₀| = 0.146), the two differing by 1.5 Monte Carlo errors; keep the recorded verdict as the preregistered one but do not write that it "stays". A one-line "PARTIAL/PASS (boundary within MC resolution)" in Table 4 and Fig. 2 would be honest.
3. Replace "identity is expected from fixed seeds and the same code path" by "… and the same numerical environment", and say that the hash-locked comparison establishes same-environment reproducibility only.
4. Add this to Sec. 5 item 3 (process failures) and to `LL.md`-style lessons: a verdict whose margin is one MC error should be preregistered with a chain long enough that the MC error is ≪ the margin, or the rule should be stated on a deterministic estimator (MAP, or a posterior mean with a preregistered MC-error floor). The preregistration's own `sigma_mc_and_numerics_allowance` of 0.05 anticipated MC noise of "~0.02"; a 4000-step chain (n/(50τ) = 2.2) does not beat that.

### m1 (minor) — the "measured formula systematic" (−0.034 / −0.0044) is Monte-Carlo-noise dominated; the MAP difference is the clean measurement
Sec. 4.3 ("Exact CAMB versus the fitting formula moves H₀ by −0.034 (DR2) and −0.0044 (DR1)"), Table 7 rows, Sec. 4.5(c). These are differences of two posterior means with independent chains; the MC error of each difference is 0.015 (T1) and 0.020 (T2), so the DR1 value −0.0044 is not "smaller", it is noise. The MAP differences are deterministic and mutually consistent: primary − secondary = −0.0419 (T1) and −0.0411 (T2), unchanged to 10⁻⁷ between the two environments, and equal to what the −0.029 % formula error at the posterior point predicts through 1/0.49 (−0.041). Please quote the MAP differences (or add the MC error to the posterior-mean ones) in Sec. 4.3, Table 7 and 4.5(c); the conclusion of 4.5(c) ("confirms Aubourg's stated accuracy") becomes stronger, not weaker.

### m2 (minor) — the cross-covariance sentence and Table 7 label describe the wrong matrix
Sec. 4.5(b) "with X = ρ√C_S√C_D subtracted from C_S + C_D" and Table 7 "with X = ρ√C_S√C_D subtracted". The script (`round1_response_checks.py`, `overlap_sensitivity`) subtracts X + Xᵀ, which is the correct covariance of a difference and gives N_σ = 1.344; subtracting X alone, as the text literally says, gives N_σ = 1.06 (PTE 0.29). Write "X + Xᵀ" (or "2X_sym").

### m3 (minor) — part of the "untraced ~10⁻⁵ remainder" in the Aubourg check is a bookkeeping inconsistency in the validation code
Sec. 4.3: "the remainder is of order 10⁻⁵ and was not traced further". `rd_camb_table.py` line 136 evaluates eq. (16) at ω_cb = ω_b + ω_cdm + ω_ν,CAMB − ω_ν,Aubourg = ω_b + ω_cdm + 2.9 × 10⁻⁶ (0.000644899 − 0.000642), i.e. the CAMB grid point (ω_b, ω_cdm) is compared with the formula at a slightly different ω_cb. That biases the formula by −0.25351 × 2.9 × 10⁻⁶/0.1412 = −5.2 × 10⁻⁶ at the worst point (recomputed: 147.53745 with ω_cb = ω_b + ω_cdm versus the stored 147.53669). Corrected, the worst point is −0.0219 % against CAMB at N_eff = 3.046, still above 0.021 % but by 0.9 × 10⁻⁵ instead of 1.4 × 10⁻⁵. The conclusion ("most but not all") stands; one sentence can trace half the remainder.

### m4 (minor) — the G2 source string cites the DR1 abstract, which contains no r_dh
Table 5 "G2 … arXiv:2404.03002 abstract/Sec. 8". The re-fetched abstract quotes Ω_m = 0.295 ± 0.015 and H₀ = 68.52 ± 0.62 only; r_dh = 101.8 ± 1.3 is in eq. (4.1) and Sec. 8. The preregistration cannot be edited; the caption of Table 5 can say so.

### m5 (minor) — the Reproducibility commands do not name an interpreter, and one script's own docstring names one that cannot run it

### m6 (minor) — the strict window's construction is quoted without its MC term
Sec. 3.2: "The strict window … was built in the preregistration from a fitting-formula systematic of 0.139". The preregistration's `strict_definition` is √(0.139² + 0.05²) = 0.148 → 0.15, where 0.05 is the `sigma_mc_and_numerics_allowance`; the "post-hoc re-budget 0.050" is that same 0.05 with the formula term removed (`fixround_diagnostics.json`, `tolerance_rebudget`). Say so; it also explains why the re-budget equals the MC allowance and connects to M1.
