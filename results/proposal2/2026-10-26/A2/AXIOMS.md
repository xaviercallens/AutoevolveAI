## Statement identity (substitute for Comparator's definition check)

**What was checked.** The proved theorems are stated over the solution-side copies of the definitions (`NavierStokes/ComparatorDefinitions.lean`, `Euler/SolutionDefinitions.lean`), not over the reference challenge file. So I compared the **elaborated** kernel terms, not the source text.

**Method (`lean_scripts/DumpCore.lean.txt`).**
- For each pair of root theorems, take the transitive "statement closure". It includes:
  - all constant types;
  - the values of definitions and opaques;
  - inductive/constructor links;
  - but not theorem proofs.
- Dump each constant's kind, universe parameters and `Expr.hash` of its type and value. For corpus constants, also dump the full raw `Expr` text of the type and value.
- Do this in two separate environments:
  1. **Reference:** the verbatim `ComparatorChallenges/*.lean` source with the dump appended. This environment imports Mathlib only.
  2. **Solution:** `import NavierStokes.ComparatorSolution` / `import Euler.Solution`.
- Compare with `scripts/compare_dumps.py`. It normalises only the module component of hygienic binder names (`x._@._stdin.N._hygCtx._hyg.M` vs `x._@.NavierStokes.ComparatorDefinitions.N._hygCtx._hyg.M`), which is alpha-renaming.

| pair | constants in closure | only in reference | only in solution | differing (after alpha-normalisation) | corpus constants text-compared |
|---|---|---|---|---|---|
| NS (C)+(D) | 5,599 / 5,599 | 0 | 0 | **0** | 23 |
| Euler (both) | 5,521 / 5,521 | 0 | 0 | **0** | 25 |

**Raw differences before normalisation.**
- NS: 4 constructor types; Euler: `toL2`, `toL2._proof_3` and `exists_compact_smooth_euler_singularity`.
- In every case `Expr.hash` was equal on both sides, and the text differed only in those hygienic binder names.
- The Euler theorem includes `Solution.lean`'s `attribute [local instance] CompletePartialOrder.toSupSet`. It elaborates to the same type hash (642579273) as the reference, so the local-instance concern is cleared.

**Negative control.** A copy of the reference was mutated, with `(∫ x, ‖v x t‖ ^ 2) < E` changed to `≤ E` (`controls/dumpdiff/`). The comparison then reports `differing=1`, on `NavierStokes.Comparator.NavierStokesExistenceAndSmoothnessRn.mk` (type hash 4044432975 → 666613966).

**Scope.**
- `Expr.hash` is used for non-corpus (Mathlib/core) constants. A collision is possible in principle, but the corpus constants are additionally compared as full text.
- A name collision on the Mathlib side would show up as a hash difference. None occurred.
- This is not Comparator: no lean4export, no nanoda, no sandbox. It checks the same property — the proved statement is the reference statement — by a different implementation.
