# GR-11 addendum 2 to PREREG_ITEM.md (2026-10-31, written before the n=11 run, at the coordinator's request)

n=11 is the same scan as n<=10: all 1,006,700,565 connected graphs from `nauty-geng -c 11`, split into 40 parts (res/40), same code/scan.py logic and threshold (violation = count > S+ + 1e-6), cores 4,5 only (one worker per core, parts alternate, one json per part, existing part files are skipped on restart). The only code change is that scan.py additionally writes to data/flagged_n11_<res>of40.txt every graph6 whose margin S+ - count is below 1e-6 for conjecture 20 or 21 (ties and any violation); the decision logic is unchanged. Every flagged graph is then decided EXACTLY: characteristic polynomial of the adjacency matrix over Z, exact positive/negative root counts by Sturm sequences (sympy), and the comparison count <= S+ decided by rational/mpmath interval arithmetic on the roots, or by an exact identity when S+ is an integer. K_n equality (S+ = n-1 = n_neg) stays a hand-proved tie. The 40 part counts must sum to exactly 1,006,700,565. The Graffiti 29 control is evaluated in the same pass (expected to fire on some graphs). Kill: if projected CPU time exceeds 20 core-hours the run stops and partial coverage (parts done) is reported.
